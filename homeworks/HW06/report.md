## 2. Protocol

### 2.1. Разбиение данных
- **Метод:** `train_test_split` с стратификацией
- **Пропорции:** 75% train (9000 образцов), 25% test (3000 образцов)
- **Параметры:** `test_size=0.25`, `random_state=42`, `stratify=y`
- **Обоснование:** Фиксированный random_state обеспечивает воспроизводимость, стратификация сохраняет баланс классов (~68%/32%)

### 2.2. Подбор гиперпараметров
- **Метод:** GridSearchCV с 5-фолдовой кросс-валидацией
- **Оптимизация:** Accuracy на валидационных фолдах
- **Процесс:** Для каждой модели перебирались комбинации параметров, лучшая выбиралась по среднему accuracy на 5 фолдах
- **Важно:** Тестовая выборка не участвовала в подборе, использовалась только для финальной оценки

### 2.3. Метрики оценки
Три метрики оценивают разные аспекты качества:

**Accuracy** - общая доля правильных предсказаний. Базовая метрика, но может вводить в заблуждение при дисбалансе классов.
**F1-score** - среднее гармоническое precision и recall. Критична при дисбалансе классов, так как оценивает качество предсказания миноритарного класса.
**ROC-AUC** - площадь под ROC-кривой. Главная метрика для бинарной классификации:
- Не зависит от порога классификации
- Устойчива к дисбалансу классов  
- Оценивает качество вероятностных предсказаний
- Обязательна по заданию для бинарных датасетов

Для нашего датасета с умеренным дисбалансом все три метрики важны: accuracy показывает общую эффективность, F1-score оценивает работу с миноритарным классом, ROC-AUC дает наиболее полную картину разделимости классов.

## 6. Conclusion

### 6.1. Про деревья и ансамбли
1. **Контроль сложности работает** - DecisionTree с подобранными параметрами не переобучается даже на идеальных данных
2. **Ансамбли не всегда лучше** - при линейно разделимых данных RandomForest и бустинг не дают преимущества над простой LogisticRegression
3. **Случайность признаков важна** - max_features в RandomForest создаёт разнообразие деревьев, но в данном случае не влияет на результат

### 6.2. Про честный ML-протокол
1. **Стратификация обязательна** - при дисбалансе классов сохраняет репрезентативность выборок
2. **Фиксированный random_state** обеспечивает полную воспроизводимость результатов
3. **Test только один раз** - строгое разделение на подбор (train/CV) и финальную оценку (test) предотвращает утечку данных
4. **GridSearchCV на train** - корректная оценка качества моделей без переобучения на тестовых данных

### 6.3. Практические инсайты
1. **Начинать с простого** - LogisticRegression показал, что не всегда нужны сложные ансамбли
2. **Синтетические данные vs реальные** - идеальные результаты редко встречаются на практике
3. **Метрики дополняют друг друга** - ROC-AUC, F1 и accuracy дают разностороннюю оценку

**Итог:** Эксперимент подтвердил важность честного ML-протокола и показал, что выбор модели должен зависеть от природы данных, а не от сложности алгоритма.
